# Event expansion (opt-in recurrence occurrence API)

The library already parses and serializes RFC 5545 components, recurrence rules
and timezones, but parsing a recurring `VEVENT` does not, by itself, answer the
question "which instances fall inside this time window?". The expansion API in
this document is an **opt-in** layer that answers exactly that question. It does
not change any existing component read/write interface: nothing about
`VEvent`, `Calendar.Serialize`, `GetStartAt` or the property API changes.

## Why not just return `[]time.Time`

An instance exists for a reason. It may come from `DTSTART`, be generated by
one or more `RRULE`s, injected by an `RDATE`, removed by an `EXDATE`, or be
replaced by a `RECURRENCE-ID` override. Two rules can generate the same
instant; a timezone can change its offset across a DST transition; a floating
time is not an absolute instant at all. The expansion result therefore carries
each surviving instance together with provenance ("sources") and preserves the
original time semantics.

## API

Two entry points:

```go
// Expand one recurring master plus its RECURRENCE-ID overrides.
func ExpandEvent(
    master *VEvent,
    windowStart, windowEnd time.Time,
    maxInstances int,
    overrides []*VEvent,
    opts ...any,
) (*Result, error)

// Group a parsed calendar by UID, pair masters with overrides, expand each.
func ExpandCalendar(
    cal *Calendar,
    windowStart, windowEnd time.Time,
    maxInstances int,
    opts ...any,
) ([]EventSeries, error)
```

`maxInstances` is required and positive: it bounds the number of instances
returned and protects callers from unbounded rules (`FREQ=DAILY` with no
`COUNT`/`UNTIL`).

### Result and evidence

```go
type Result struct {
    Instances  []*Instance        // ascending, inside the window
    Truncated  bool               // stopped because MaxInstances / safety limit
    Truncation TruncationReason   // TruncationMaxInstances | TruncationSafetyLimit
    Diagnostics Diagnostics       // populated only with WithDiagnostics()
}

type Instance struct {
    Start      DateTime   // original semantics (UTC / TZID / floating / date)
    End        DateTime   // master duration applied to this occurrence
    Sources    []Source   // why this instance exists, sorted for stability
    Override   *Override  // RECURRENCE-ID component replacing it, if any
    Suppressed bool       // removed (only reachable via diagnostics)
}

type Source struct {
    Kind       SourceKind // DTSTART | RRULE | RDATE | EXDATE | EXRULE | RECURRENCE-ID
    RuleIndex  int        // which RRULE/EXRULE property
    Value      string     // raw property value, for debugging
}
```

Source categories:

- `SourceStart` — the original `DTSTART` instance.
- `SourceRRule` — generated by an `RRULE` (the rule index disambiguates several).
- `SourceRDate` — injected by an `RDATE`.
- `SourceExclusion` / `SourceExRule` — why an occurrence was removed (diagnostics only).
- `SourceOverride` — a `RECURRENCE-ID` override took effect.

When two rules (or `DTSTART` and a rule) produce the same instant they are
merged into one `Instance` that keeps every `Source`.

`DateTime` keeps the value kind separately from the Go `time.Time`:

- `TimeKindUTC` — trailing `Z`, location is `time.UTC`.
- `TimeKindTZID` — local wall time with a resolved `TZID` (`DateTime.TZID`
  retains the original identifier).
- `TimeKindFloating` — no `TZID`, no `Z`. Evaluated in a dedicated fixed
  `FLOATING` zone, **never** `time.Local`, so host settings cannot affect it.
- `TimeKindDate` — `VALUE=DATE` all-day value.

## Window and termination semantics

- The window is half-open by default: `[windowStart, windowEnd)`. Pass
  `WithInclusiveWindowEnd()` to make both ends inclusive.
- Anchored values (UTC/TZID) are compared by absolute instant; floating and
  date values by wall-clock components.
- `COUNT` counts `DTSTART` as occurrence number one, even when `DTSTART` does
  not itself satisfy the `BY-*` pattern (RFC 5545 §3.8.5.3).
- `UNTIL` is inclusive. A date-time `UNTIL` is compared as a UTC instant; a
  date-only `UNTIL` covers the entire `DTSTART`-local day.
- `BYSETPOS` positions count within the full rule period, including days in the
  first period that precede `DTSTART`; those days participate in position
  counting but are not themselves emitted.
- Month positions that do not exist (the 31st, Feb 29 in a common year) yield
  no occurrence; they are never normalized forward.
- DST: a non-existent local wall time during a spring-forward gap is
  interpreted with the offset in force immediately before the gap
  (e.g. `02:30 EST` denotes `03:30 EDT`), per RFC 5545 §3.3.5. An ambiguous
  fall-back wall time denotes its first (daylight) occurrence.
- When `MaxInstances` in-window instances are reached, expansion stops,
  `Result.Truncated` is `true`, `Truncation` is `TruncationMaxInstances`, and
  the returned error satisfies `errors.Is(err, ErrExpansionTruncated)`. This is
  deliberately distinguishable from a rule that ended naturally via
  `COUNT`/`UNTIL`.

## `EXDATE`, `RDATE`, overrides

- `EXDATE` removes the matching occurrence. Matching follows RFC 5545: same
  time type and wall clock; an anchored value in a different kind also matches
  when the absolute instants coincide. Floating values match only floating
  values, and date values only date values.
- `RDATE` adds an occurrence. When an `EXDATE` and an `RDATE` name the same
  instant, the `EXDATE` wins (the date is authoritatively declared absent).
- A `RECURRENCE-ID` override replaces the matching occurrence: a different
  `DTSTART` reschedules it, `STATUS:CANCELLED` suppresses it. An override that
  does not match any generated occurrence is emitted as an "orphan" instance
  marked via `Override.Orphan`.
- Removed occurrences never appear in `Instances`; with `WithDiagnostics()`
  they are listed in `Result.Diagnostics.Excluded` with the exact reason.

## Timezones

- IANA `TZID` values resolve through the host tz database.
- Embedded `VTIMEZONE` blocks are compiled automatically by `ExpandCalendar`
  (via `time.LoadLocationFromTZData`), so calendars that define their own zones
  work on hosts without matching IANA data.
- Supply `WithTimezoneResolvers(...)` to map non-standard identifiers
  (e.g. legacy names). A `TZID` that nothing can resolve returns an error
  wrapping `ErrUnknownTimezone` rather than silently using the host zone.

## Complete example: weekly series crossing a DST change with an override

```go
package main

import (
	"errors"
	"fmt"
	"strings"
	"time"

	ics "github.com/arran4/golang-ical"
)

const data = "BEGIN:VCALENDAR\r\n" +
	"VERSION:2.0\r\nPRODID:example\r\n" +
	// Embedded zone; works even without host IANA data.
	"BEGIN:VTIMEZONE\r\nTZID:America/New_York\r\n" +
	"BEGIN:DAYLIGHT\r\nTZOFFSETFROM:-0500\r\nTZOFFSETTO:-0400\r\nTZNAME:EDT\r\n" +
	"DTSTART:19700308T020000\r\nRRULE:FREQ=YEARLY;BYMONTH=3;BYDAY=2SU\r\nEND:DAYLIGHT\r\n" +
	"BEGIN:STANDARD\r\nTZOFFSETFROM:-0400\r\nTZOFFSETTO:-0500\r\nTZNAME:EST\r\n" +
	"DTSTART:19701101T020000\r\nRRULE:FREQ=YEARLY;BYMONTH=11;BYDAY=1SU\r\nEND:STANDARD\r\n" +
	"END:VTIMEZONE\r\n" +
	// Master: every weekday at 09:00, 90 minutes long.
	"BEGIN:VEVENT\r\nUID:standup\r\n" +
	"DTSTART;TZID=America/New_York:20240304T090000\r\n" +
	"DTEND;TZID=America/New_York:20240304T103000\r\n" +
	"RRULE:FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR;COUNT=20\r\n" +
	"EXDATE;TZID=America/New_York:20240312T090000\r\n" +
	"END:VEVENT\r\n" +
	// Override: the Friday March 15 standup moves to 11:00 and changes summary.
	"BEGIN:VEVENT\r\nUID:standup\r\n" +
	"RECURRENCE-ID;TZID=America/New_York:20240315T090000\r\n" +
	"DTSTART;TZID=America/New_York:20240315T110000\r\n" +
	"DTEND;TZID=America/New_York:20240315T123000\r\n" +
	"SUMMARY:Late standup\r\nEND:VEVENT\r\n" +
	"END:VCALENDAR\r\n"

func main() {
	cal, err := ics.ParseCalendar(strings.NewReader(data))
	if err != nil {
		panic(err)
	}

	winStart := time.Date(2024, 3, 1, 0, 0, 0, 0, time.UTC)
	winEnd := time.Date(2024, 3, 25, 0, 0, 0, 0, time.UTC)

	series, err := ics.ExpandCalendar(cal, winStart, winEnd, 100, ics.WithDiagnostics())
	if err != nil && !errors.Is(err, ics.ErrExpansionTruncated) {
		panic(err)
	}

	for _, s := range series {
		for _, inst := range s.Result.Instances {
			var why []string
			for _, src := range inst.Sources {
				why = append(why, string(src.Kind))
			}
			summary := ""
			if inst.Override != nil {
				if p := inst.Override.Component.GetProperty(ics.ComponentPropertySummary); p != nil {
					summary = " (" + p.Value + ")"
				}
			}
			// Every event stays 09:00 local even though UTC offset changes on
			// March 10 (EST -> EDT); March 12 is EXDATEd; March 15 is moved.
			fmt.Printf("%s %s-%s %v%s\n",
				inst.Start.Time.Format("Mon 2006-01-02"),
				inst.Start.Time.Format("15:04"),
				inst.End.Time.Format("15:04"),
				why, summary)
		}
		for _, ex := range s.Result.Diagnostics.Excluded {
			fmt.Printf("excluded: %s\n", ex.Start.Time.Format("Mon 2006-01-02 15:04"))
		}
	}
}
```

Output (note the constant `09:00–10:30` local wall time across the DST
transition, the missing Tuesday March 12, and the rescheduled Friday):

```
Mon 2024-03-04 09:00-10:30 [DTSTART RRULE]
Tue 2024-03-05 09:00-10:30 [RRULE]
Wed 2024-03-06 09:00-10:30 [RRULE]
Thu 2024-03-07 09:00-10:30 [RRULE]
Fri 2024-03-08 09:00-10:30 [RRULE]
Mon 2024-03-11 09:00-10:30 [RRULE]
Wed 2024-03-13 09:00-10:30 [RRULE]
Thu 2024-03-14 09:00-10:30 [RRULE]
Fri 2024-03-15 11:00-12:30 [RRULE RECURRENCE-ID] (Late standup)
Mon 2024-03-18 09:00-10:30 [RRULE]
...
excluded: Tue 2024-03-12 09:00
```

## Determinism and round trips

Expansion is deterministic and independent of Go map iteration order and the
host's default timezone. A calendar serialized with `Serialize` and re-parsed
produces, for the same window, identical instance instants, source categories
and override relationships (covered by `TestExpandSerializationRoundTrip`).
